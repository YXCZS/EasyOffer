## Why

当前题目生成流程以个人 Chroma 检索优先，并在没有本地结果时调用 Tavily；“新概念直接联网”无法判断个人资料是否已经包含该知识，也无法处理版本变化、证据不足和资料冲突。需要一个受控的 Agentic RAG 路由，让系统以较低成本优先复用个人知识库，并在证据不足或需要时效信息时可靠地补充 Tavily Search/Extract。

## What Changes

- 新增统一的证据路由能力，由 Router Agent 在个人知识库、Tavily Search、Tavily Extract、混合检索和基础模型降级之间制定检索计划。
- 增加 URL、明确时效要求、明确使用个人资料等确定性路由约束，避免 Agent 对强制场景做出不稳定选择。
- 将个人 Chroma 检索作为可评估的工具，依据相关性、覆盖度、可回答性和冲突情况决定接受、补充联网或切换联网。
- 对普通主题采用本地优先，对低置信度、版本敏感、资料冲突和新颖性不确定的主题按需调用 Tavily；URL 优先使用 Tavily Extract。
- 增加中英文查询改写、Tavily 搜索深度/结果数量/页面提取深度的受控动态策略，并限制单次请求的工具调用次数。
- 统一证据融合、来源标记、引用保留、超时、日志和降级逻辑，避免题目生成过程中重复调用 Tavily。
- 生成题目后增加证据约束和结构校验；联网失败时继续使用可用的个人资料或原有基础模型流程，不影响现有答题和报告流程。

## Capabilities

### New Capabilities

- `agentic-evidence-routing`: 为技术面试题目生成提供受控的 Chroma/Tavily 路由、证据评估、混合检索、来源融合和失败降级能力。

### Modified Capabilities

无。现有题目生成、答题、报告、底部导航和断点续答能力的用户行为保持不变；本变更只扩展题目生成前的证据获取和校验过程。

## Impact

- 后端 `app/research`、`app/llm`、题目生成服务及其配置、日志和测试。
- Chroma 个人知识库检索接口需要以 Agent Tool 形式暴露，并增加证据评分/融合的数据结构。
- Tavily Search/Extract 调用策略和缓存、超时、调用预算需要统一管理。
- 题目生成接口响应中的证据元数据可能增加路由、来源类型、调用次数和降级原因；现有字段保持兼容。
- 需要新增 pytest 后端测试、Tavily/Chroma mock 测试、超时降级测试，并执行前端 typecheck、微信小程序构建和核心流程验证。
