## Context

当前题目生成流程在用户登录时先调用个人 Chroma，只有本地没有结果时才调用 Tavily；生成器还可能再次调用研究提供者，造成重复联网。Tavily Agent 当前只负责 Search/Extract 的选择，Chroma 不在同一个 Agent 的工具集合中。此次设计需要在不改变答题、报告、底部导航和断点续答的前提下，统一证据获取路径。

## Goals / Non-Goals

**Goals:**

- 用结构化、可解释的 Router Agent 选择 Chroma、Tavily Search、Tavily Extract 或组合路径。
- 以个人知识库优先降低成本，以证据质量、时效性和冲突情况决定是否联网。
- 限制工具调用次数、超时和上下文长度，保证微信端生成体验可接受。
- 保留来源和路由元数据，并在外部服务失败时兼容原有基础模型降级。
- 通过离线样本和 pytest 验证路由正确性、证据约束和失败恢复。

**Non-Goals:**

- 不训练新的路由模型或完整 Self-RAG 基础模型。
- 不引入固定技术词表来判断新旧技术。
- 不改变题目、答题、报告、用户系统和知识库上传的用户界面。
- 不增加城市级搜索逻辑，不把 Tavily 结果永久写入用户个人 Chroma。

## Decisions

### 1. 采用“规则门控 + 受限 Agent”而不是完全自由的 Agent

URL、明确最新要求、明确使用个人资料等条件由确定性门控处理；其余不明确请求交给 Router Agent。Agent 使用结构化输出和工具预算，最多规划有限轮次。这样保留 Agent 的灵活性，同时避免无限调用、成本失控和强制场景误路由。

备选方案：完全依赖 LLM 自由调用工具。该方案实现简单，但调用次数、延迟、可重复性和测试难度都较差，不适合当前产品。

### 2. 采用“本地优先、证据纠错、按需联网”的三段式路由

有个人知识库且无强制联网条件时，先执行 Chroma 检索。对结果做相关性、覆盖度、可回答性和冲突评估：高置信度直接使用；中置信度保留本地证据并补充 Web；低置信度改用 Web。明确时效或 URL 场景可以跳过本地优先策略。

备选方案：始终并行 Chroma 和 Tavily。准确率可能较高，但每次生成都会消耗联网配额、增加延迟，也会把无关网络噪声引入题目。

### 3. 将 Chroma、Tavily Search、Tavily Extract 统一为证据工具

三个工具返回统一的 EvidenceItem，包括内容、来源类型、来源标识、URL、时间和分数。Router Agent 只负责编排检索，题目生成器只接收最终 EvidenceContext，消除当前 `build_evidence_context` 与 `research_provider` 的重复调用。

### 4. 采用分层证据评估，避免每次都额外调用大模型

第一层使用向量相关性、关键词覆盖、文档状态和元数据进行快速评分；只有中间分数、冲突或高风险主题才调用轻量 Evidence Grader。阈值必须通过离线标注样本校准，不能永久依赖某个固定 Chroma 分数。

### 5. Tavily 参数由路由计划动态决定

简单主题使用 basic 搜索和较少结果；复杂、版本敏感或低置信主题使用 advanced 搜索并增加结果数；只有摘要不足时才 Extract 最相关的页面。搜索查询保留原始英文技术词，并可生成中文/英文面试语境查询，不使用城市参数。

### 6. 采用公共研究缓存和严格的失败降级

对不包含个人数据的公共搜索和页面提取结果按查询、岗位和时效策略缓存；个人知识库结果禁止跨用户共享。每次请求设置总预算和超时，Tavily 失败时依次使用高质量本地证据、已有压缩证据和原有基础模型。所有降级记录 route、失败类型、工具调用数和耗时。

### 7. 生成后执行轻量校验，重点覆盖高风险请求

所有请求执行 JSON 结构、题目数量和主题相关性校验；联网、低置信或存在冲突的请求额外执行证据一致性检查。校验失败最多受控重试一次，重试不重新发起相同的联网搜索。

## Risks / Trade-offs

- [路由 Agent 误判] → 用 URL/最新/个人资料规则做强制门控，并使用结构化输出和路由日志。
- [Chroma 分数跨模型不可比] → 通过离线样本校准阈值，结合覆盖度和可回答性，不只看单一分数。
- [Tavily 延迟或配额不足] → 单次调用预算、超时、公共缓存和基础模型降级。
- [网络来源质量参差] → 优先官方文档、GitHub 和一手来源，保留 URL/抓取时间，并对冲突显式标记。
- [混合上下文过长] → 去重、重排、按来源和字符数裁剪后再传给 DeepSeek。
- [旧逻辑重复联网] → 由统一 Retrieval Agent 产出唯一 EvidenceContext，生成器不再独立调用研究提供者。

## Migration Plan

1. 先增加统一证据模型、工具接口、路由计划和特性开关，保留现有生成接口。
2. 接入 Chroma Tool 和 Router Agent，在灰度开关关闭时继续使用现有路径。
3. 接入证据评估、混合检索、缓存、预算和失败降级，完成后切换默认路径。
4. 删除或禁用生成器中的重复研究调用，验证现有核心流程后再清理旧分支。
5. 若出现错误率、延迟或成本异常，关闭特性开关即可回退到现有证据流程；不需要数据库迁移和用户数据回滚。
