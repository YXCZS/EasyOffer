## Context

当前后端已经有用户隔离的 `quiz_progress` 表和删除进度路由，删除接口会把活动练习标记为 `abandoned`；首页只查询 `in_progress` 与 `ready_for_report`。知识库文档使用 `knowledge_documents.original_name` 展示，删除、重试和 ready 状态校验已经存在。前端首页和知识库页均为 Taro 页面，并通过统一 API 服务访问后端。

## Goals / Non-Goals

**Goals:**

- 复用现有进度放弃接口，让用户从未完成列表安全移除练习，并兼容网络重试。
- 增加仅限文档所有者的名称更新接口，名称修改不触发文件解析、向量化或文档 ID 变化。
- 在知识库页面提供轻量的名称编辑交互，并把 ready 文档入口文案统一为“开始答题”。
- 保持现有普通答题、知识库专属答题、进度恢复、报告生成和历史查询流程不变。

**Non-Goals:**

- 不物理删除 `quiz_sessions`、`quiz_progress` 或已完成历史；放弃练习只改变状态。
- 不修改文件内容、重新切分文档、重建 Chroma 向量或改变单文档检索规则。
- 不新增账户体系、底部导航、批量管理或跨用户共享文档能力。

## Decisions

### 1. 练习删除采用逻辑放弃

继续使用现有 `DELETE /api/v1/user/quizzes/{quiz_id}/progress`，由仓储将 `in_progress`/`ready_for_report` 更新为 `abandoned`。这样无需数据库迁移，能够保留审计和并发版本信息；首页现有查询天然会隐藏它。物理删除会破坏恢复、调试和历史关联，因此不采用。

重复请求若记录已经是 `abandoned` 或不存在，前端按“已移除”处理并刷新列表；后端可以返回 404，不能暴露题目内容。

### 2. 文档名称使用 PATCH 接口更新

新增 `PATCH /api/v1/knowledge/documents/{document_id}`，请求体只包含 `original_name`。路由先按当前用户查询文档，再校验去首尾空白后的非空长度，仓储执行带 `user_id` 和 `document_id` 条件的更新并返回最新文档。

只更新数据库展示名称，不改 `storage_path`、`content_hash`、`document_id`、处理状态或 Chroma 分片。这样改名是低成本即时操作，也不会让正在处理的文档进入重复任务。后续点击“开始答题”仍传原文档 ID，session 使用最新名称作为展示名称。

### 3. 前端采用卡片内联编辑与确认反馈

知识库卡片保留现有布局：名称区域进入编辑态后显示输入框和“保存/取消”，保存成功更新本地列表；失败显示接口错误并恢复原名称。名称编辑不阻塞删除、重试等既有动作。

首页未完成卡片增加删除图标/文字操作，点击后使用现有 `showModal` 二次确认。确认后调用放弃接口，成功或已不存在均移除本地卡片并重新拉取列表；取消不调用接口。

ready 文档按钮只替换显示文本为“开始答题”，路由、`document_id`、生成页和后端 `knowledge_only` 参数全部复用现有实现。

### 4. 兼容与错误映射

- 未登录用户继续沿用现有认证拦截，不能删除练习或修改文档名称。
- 文档不存在或不属于当前用户统一返回 404，不返回他人名称。
- 名称校验失败返回 422/400 级别参数错误，前端保留旧名称。
- 练习删除遇到网络错误保留卡片并提示重试，避免本地与服务端状态不一致。

## Risks / Trade-offs

- [风险] 已有向量元数据中的 `source_name` 可能仍是上传时文件名。→ 本次只保证列表、入口和新练习展示名称；向量内容和引用身份不变，避免为改名重建索引。
- [风险] 用户连续点击删除或保存造成重复请求。→ 前端操作期间禁用当前控件，后端使用用户 ID 条件和幂等状态更新。
- [风险] 旧版本客户端没有名称编辑字段。→ 新字段为独立 PATCH 接口，旧客户端继续读取原有 `original_name`，不影响生成和答题。
- [风险] 删除请求成功但列表刷新失败。→ 先更新本地卡片并提示刷新失败，下一次进入首页仍会从服务端状态恢复一致结果。

## Migration Plan

无需数据库迁移。部署后端接口和前端页面即可；回滚时移除新入口，已标记 `abandoned` 的记录仍保留，不会影响继续答题或已完成历史数据。
