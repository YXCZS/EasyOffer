## Context

现有后端已经有 `evidence` 路由、Chroma 个人知识库、LangChain Tavily Search/Extract、DeepSeek 出题和增量任务快照。关键词研究当前主要依赖单个路由查询，Tavily 结果去重后直接进入出题上下文；URL 研究可以提取页面，但长正文也缺少面向用户主题的内容块筛选。现有文档专属模式必须继续禁止公共联网，研究失败时基础模型降级和增量任务异步生命周期不能回归。

本设计采用 LangChain 官方 Tavily 工具作为执行层。当前安装版本的 `TavilySearch` 支持 `search_depth`、`max_results`、`include_raw_content` 等参数，`TavilyExtract` 支持 `urls`、`extract_depth`、`format` 和按主题过滤的 `query`；本变更不使用时间范围参数。

## Goals / Non-Goals

**Goals:**

- 对所有进入关键词联网搜索的主题强制执行一次结构化查询扩展。
- 在有限查询数、结果数和总超时内并行获取多视角资料。
- 让搜索结果和 URL 提取正文都经过同一套主题相关性过滤后再进入出题 Prompt。
- 保留来源 URL、片段、评分、主张和过滤状态，支持日志排障和题目来源展示。
- 将研究阶段错误隔离在证据准备阶段，不阻塞异步任务创建，不删除已生成题目和答题记录。
- 复用现有 Agentic RAG、Tavily、DeepSeek、MySQL 任务 JSON 和前端接口，不增加新的外部框架或数据库表。

**Non-Goals:**

- 不增加前端搜索时效选择，不使用 `time_range`、`start_date` 或 `end_date`。
- 不改变 Agentic RAG 的个人知识库路由规则、文档专属模式、增量逐题生成和答题/报告页面。
- 不让 Agent 无上限地自主生成查询、循环调用工具或把未过滤结果作为兜底上下文。
- 不在本变更中重写题目质量校验、报告生成或 Chroma 分块算法。

## Decisions

### 1. 使用结构化 Query Planner，而不是让 Agent 自由循环扩展

新增一次 DeepSeek 结构化调用，输入原始主题、岗位、难度，输出 `canonical_topic`、`queries`、`important_terms` 和 `intent`。后端强制限制 1-3 个查询、去除空值/重复值，并验证每个查询至少包含原始主题的关键术语。查询规划失败时最多重试一次，然后以规范化原始主题作为唯一查询。

选择该方式是因为 Agent 自由循环会使查询数量、Token 和延迟不可预测；固定 Planner 保留语义扩展能力，同时让 Tavily 调用预算可测试。相比仅在 Prompt 中要求 Tavily 自己改写查询，独立结构化输出更容易记录和回归。

### 2. Tavily 查询并行执行，后端控制工具预算

Planner 输出的查询由后端使用有限并发并行调用 `TavilySearch`。简单查询使用 `basic`/较少结果，复杂或新概念使用 `advanced`/较多结果，但最终查询数不超过 3、每次结果数不超过配置上限、总研究时间受统一超时约束。每个查询独立捕获异常；成功结果继续合并，全部失败才触发基础模型降级。

URL 输入不经过 Planner，直接使用 `TavilyExtract` 获取页面内容。提取请求限制 URL 数量和正文长度；单页长内容按标题/段落优先、长度上限切分为候选块。

### 3. 采用“两阶段过滤”：规则去重后一次 AI 评分

Tavily 结果或 Extract 内容块先经过确定性处理：规范化 URL、内容指纹去重、标题/正文长度检查、保留标题/站点/检索时间和原始 URL。候选数量限制在可控范围内后，统一交给 DeepSeek 相关性过滤器。

过滤器输出严格结构化的 `source_id`、`relevance_score`、`keep`、`reason`、`claims`、`version_fit` 和可选 `conflict_group`。只有评分达到阈值且 `keep=true` 的候选进入 `EvidenceContext`；最多保留 5 个高质量来源/内容块。过滤失败最多重试一次，仍失败时不把未过滤结果注入 Prompt，而是走基础模型降级。这样比“过滤失败直接使用全部搜索结果”更能保证可信定位和 Token 上限。

### 4. 搜索与 URL 提取共用证据模型，但保留来源类型

过滤后的结果统一转换为 `EvidenceItem`，`source_type` 分别为 `web` 或 `web_extract`，并携带 `citation`、`title`、`site`、`retrieved_at`、相关性评分和主张。证据 Prompt 继续使用不可信外部资料包装，明确禁止将网页内容当作系统指令。`evidence_meta` 增加 query plan、候选数、保留数、filter status 和 fallback reason，兼容现有题组快照。

### 5. 研究阶段降级与增量任务隔离

查询规划、每次 Tavily 调用、过滤调用分别设置超时和单次重试。研究失败只影响 `evidence_text` 与研究元数据：关键词扩展失败可用原始查询；部分搜索失败使用已成功结果；全部搜索失败、过滤失败或无高相关证据时不注入外部资料，继续使用基础模型。任务创建仍立即返回，资料准备在后台执行；已有题目和答题记录不因后续研究失败而清空。

### 6. 缓存版本和观测字段

研究缓存键必须包含规范主题、岗位、难度、查询规划版本和过滤版本，避免旧的单查询缓存绕过新过滤器。日志记录查询数量、成功/失败查询数、候选数、保留数、各阶段耗时和降级原因，但不记录 API Key 或完整敏感用户输入。无需新增数据库表，任务请求 JSON 和题组 `evidence_meta` 承载兼容字段。

## Risks / Trade-offs

- [新增两次模型调用导致首题更慢] -> Planner 和过滤器各自设置短超时、最多一次重试；Tavily 查询并行；资料准备总预算不超过现有增量证据超时；缓存成功研究结果。
- [Planner 错误扩展到无关技术] -> 结构化 Schema、原始术语覆盖校验、最多 3 个查询和原始主题回退；记录扩展查询供回归分析。
- [AI 过滤误删关键证据] -> 保留相关性分数和理由；设置最低保留数量与官方来源优先规则；过滤为空时明确降级而不是伪装成完整联网研究；后续用黄金主题集调阈值。
- [过滤模型被网页 Prompt Injection 干扰] -> 网页内容作为不可信字段包裹，过滤器系统提示明确只做相关性判定，不执行候选文本指令；输出使用 Pydantic 校验。
- [部分来源冲突被误删] -> 过滤输出保留 `conflict_group` 和版本适配字段；高质量冲突来源保留为辨析证据，不用单一相似度强行覆盖。
- [第三方服务持续不可用] -> 研究阶段失败不阻塞任务创建；基础模型生成可继续；前端已有生成状态和重试入口保持不变。

## Migration Plan

1. 先增加 Planner、过滤器输出模型和纯函数去重/评分测试，不改变现有 API 入参。
2. 在研究服务中接入关键词扩展、并行搜索和过滤；URL Extract 复用过滤器处理内容块。
3. 将过滤后证据接入现有 `EvidenceContext` 和 `evidence_meta`，保留旧字段读取兼容。
4. 运行后端 pytest、compileall、前端 typecheck 和微信构建，再用真实 DeepSeek/Tavily 验证普通主题、口语化多知识点、URL、部分失败和全失败降级。
5. 如需回滚，关闭新研究过滤开关并恢复基础模型路径；不需要数据库迁移，已有任务 JSON 和题组数据仍可读取。
