## Purpose

让用户能够把自己的面试资料安全地上传并转换为可检索的个人知识库，后续生成题目和报告时可引用这些资料，同时保证文档归属、处理状态和删除结果清晰可见。

## ADDED Requirements

### Requirement: 用户可以上传受支持的面试文档

系统 MUST 允许已登录用户上传 PDF、Word 或 Markdown 文档，并在上传前校验文件格式、文件大小和用户身份；不支持的文件 MUST 被拒绝且不得进入处理队列。

#### Scenario: 上传合法文档

- **WHEN** 已登录用户选择一个合法格式且未超过限制的文档并确认上传
- **THEN** 系统创建属于该用户的文档记录，状态显示为 `processing`，并返回文档标识

#### Scenario: 拒绝非法文档

- **WHEN** 用户上传不支持的格式、空文件或超过大小限制的文件
- **THEN** 系统返回明确的校验错误，不创建可检索文档记录，也不写入向量数据

### Requirement: 文档处理状态必须可追踪

系统 MUST 将文档处理状态表示为 `processing`、`ready` 或 `failed`，并向用户展示文件名、大小、上传时间、状态和失败原因；处理失败 MUST 提供重试入口。

#### Scenario: 文档处理成功

- **WHEN** 文档解析、文本切分和向量化全部完成
- **THEN** 文档状态变为 `ready`，用户可以在个人知识库中检索到该文档内容

#### Scenario: 文档处理失败

- **WHEN** 文档解析、向量化或持久化过程中发生不可恢复错误
- **THEN** 文档状态变为 `failed`，用户看到可读失败原因，且重试不会产生重复文档或重复向量

### Requirement: 知识库数据必须按用户隔离

系统 MUST 保证用户只能查看、检索、重试和删除自己上传的文档及其向量数据；任何跨用户文档标识访问 MUST 返回未找到或无权限，且不得泄露文件名、文本或向量内容。

#### Scenario: 用户查看个人知识库

- **WHEN** 用户打开知识库列表
- **THEN** 系统只返回当前账号拥有的文档及其处理状态

#### Scenario: 跨用户访问文档

- **WHEN** 用户 A 使用用户 B 的文档标识查询、重试或删除
- **THEN** 系统拒绝请求，不返回文档内容或元数据，也不改变用户 B 的数据

### Requirement: 用户可以管理文档生命周期

系统 MUST 支持用户删除文档；删除成功后，文档元数据、原文件和对应向量 MUST 不再参与后续个人知识库检索。删除操作 MUST 可重复执行而不会产生错误副作用。

#### Scenario: 删除已就绪文档

- **WHEN** 用户删除状态为 `ready` 的文档并确认
- **THEN** 系统删除该文档及其向量，知识库列表移除该文档，后续检索不再返回其内容

#### Scenario: 重复删除文档

- **WHEN** 客户端因网络重试重复提交同一删除请求
- **THEN** 系统返回幂等成功结果，不创建新记录、不影响其他文档

### Requirement: 知识库不可用时不阻断核心流程

个人知识库为空、文档仍在处理中或检索服务暂时不可用时，系统 MUST 保留原有题目生成和报告生成流程，并向日志记录降级原因。

#### Scenario: 用户尚无可用文档

- **WHEN** 用户生成题目或报告时没有状态为 `ready` 的个人文档
- **THEN** 系统不注入个人知识库内容，继续使用现有联网搜索或基础模型流程
