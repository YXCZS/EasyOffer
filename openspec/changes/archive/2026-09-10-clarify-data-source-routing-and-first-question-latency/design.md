## Context

当前生成任务已经采用异步任务和逐题追加，但登录用户的默认路由仍可能触发个人知识库检索，游客也可能进入联网工具；此外，证据准备在首题生成前存在较长的等待链路。设计需要在保持现有答题首页、知识库入口和图片开关不变的前提下，收紧数据源权限并缩短首题感知延迟。

## Goals / Non-Goals

**Goals:**

- 以请求入口而不是登录状态决定是否允许个人知识库。
- 让游客走低成本基础模型路径。
- 让普通登录用户的 Agent 只负责基础模型与公共网络之间的选择。
- 让知识库任务强制绑定单一文档，并允许安全的基础模型兜底。
- 保持逐题生成，给首题设置独立证据预算，并让图片完全异步。

**Non-Goals:**

- 不新增首页“是否使用个人知识库”开关。
- 不改变底部“答题/我的”导航、题型、报告结构或知识库上传流程。
- 不把逐题生成改为六题并行，也不引入 SSE。
- 不在本变更中更换 DeepSeek、Tavily、Chroma、COS 或图片模型。

## Decisions

### 1. 以入口建立策略边界

生成请求中的 `document_id`/`knowledge_only` 是进入知识库专属模式的唯一信号。无 `document_id` 时，即使用户已登录，也不得把 `user_id` 解释为“可使用个人知识库”。游客携带 `document_id` 直接拒绝。

替代方案：继续按登录状态自动混合检索。放弃原因是行为不可见、增加成本和延迟，并且与当前 UI 不一致。

### 2. 游客跳过所有检索工具

游客策略的允许工具集合只包含基础模型。主题范围校验可以保留，但不得调用 RAG 或公共搜索。这样可以降低外部依赖故障对游客流程的影响。

替代方案：游客也使用 Tavily 以提高新知识准确性。放弃原因是产品明确要求游客只能使用普通基础模型，且联网调用会增加成本和等待。

### 3. 普通登录用户采用有限 Agent 路由

无文档的登录请求允许 Agent 在 `base_model`、`tavily_search`、`tavily_extract` 间选择。查询扩展和证据过滤仅属于联网路径，不得触发 Chroma。Agent 失败时回退到确定性路由或基础模型。

替代方案：所有复杂主题强制联网。放弃原因是简单题目会产生不必要的调用，且基础模型路径是必要的可靠兜底。

### 4. 知识库任务采用文档隔离和基础模型兜底

有 `document_id` 时跳过公共网络路由，直接检索指定文档切片。证据为空、低质量或检索异常时，将限制说明注入出题上下文并使用基础模型生成，来源元数据必须区分“文档证据”和“基础模型兜底”。

替代方案：文档不足时自动搜索 Tavily。放弃原因是会违反用户选择“只学习该知识库”的预期。

### 5. 首题使用软超时，后续继续完整生成

证据准备与主题判断并行启动；为首题设置较短、可配置的证据预算。预算内使用有效证据，超时则使用已收集证据或基础模型先生成首题，剩余证据任务不得继续阻塞首题。后续题目沿用现有串行多样性校验。

替代方案：等待完整证据后再逐题生成。放弃原因是首题等待时间不可预测，无法体现增量生成价值。

### 6. 采用自适应轮询而不是 SSE

首题未就绪时前端短轮询，首题出现后进入答题页并以较长间隔拉取后续题目；网络失败采用指数退避并设置上限。保留现有 HTTP 接口，避免微信小程序对 SSE 的适配成本。

## Risks / Trade-offs

- [联网证据可能在首题之后才返回] → 题目允许基础模型先生成，记录降级原因；后续题目可以使用后来到达的证据，但不修改已经展示的题目。
- [游客题目缺少最新资料] → 在游客界面明确基础模型模式，登录后再提供联网增强能力。
- [策略边界调整导致历史任务行为不同] → 仅对新创建任务生效，历史快照按已有来源元数据展示。
- [前端轮询过频增加请求量] → 只在首题阶段使用短间隔，首题后恢复较长间隔并对失败退避。
- [图片后台任务在服务重启后遗留] → 保留 pending/failed 状态，并在后续任务恢复机制中补偿；图片状态不影响题目可用性。

## Migration Plan

1. 先发布后端策略边界和首题截止时间配置，保持现有接口字段兼容。
2. 发布前端自适应轮询和状态文案。
3. 用游客普通主题、登录普通主题、网址主题和知识库文档主题分别验证来源元数据及禁止工具调用。
4. 若出现异常，通过配置关闭联网增强或回退到基础模型路径；不需要数据库结构迁移。
