## Context

当前生成任务已经异步化，并按题目逐条写入数据库；登录用户的证据流程可以访问 Chroma 和 Tavily，但游客路径不会创建证据上下文。现有研究模块已有 Tavily Search/Extract、Query Expansion、去重和 AI 过滤能力，但路由主要由规则函数决定，且生成服务默认没有向游客提供研究 Provider。详细动机和行为范围见 `proposal.md` 以及两个新增能力规格。

## Goals / Non-Goals

**Goals:**

- 允许游客安全地创建普通主题任务，并让游客在当前匿名会话中完成答题和报告。
- 用受约束的 LangChain Agent 完成工具选择和调用，保留硬性权限边界与成本预算。
- 统一登录用户和游客的公共研究流水线；游客只能使用公共网络工具和基础模型。
- 让 Agent 输出可审计的路由、工具调用、证据和降级元数据，并兼容现有增量题目任务。
- 通过功能开关、超时、重试、缓存和限流控制成本及回滚风险。

**Non-Goals:**

- 不让游客访问或上传个人知识库，不改动 Chroma 的数据隔离模型。
- 不允许 Agent 无限循环、自动执行网页指令、调用未注册工具或修改业务数据。
- 不新增搜索时效选择器，不改变答题页、报告页和底部导航的交互结构。
- 不把一次性生成恢复为整组等待；首题仍需尽早可用。

## Decisions

### 1. 采用“策略守门 + 有限工具调用 Agent + 证据校验”的三层架构

先由后端生成不可绕过的 `PolicyEnvelope`：是否登录、是否指定文档、输入是否 URL、可用工具集合和硬性预算。再由 LangChain Agent 在该集合中自主选择工具并调用；最后由独立的结构化证据过滤器校验相关性、来源和冲突。

Agent 可以自主决定“查个人知识库、搜网络、提取网页或组合使用”，但不能突破守门策略。相比完全自由的 Agent 循环，这种方式更容易限制成本、复现问题和保证文档专属模式；相比纯规则路由，它能处理新技术、口语输入和多知识点输入。

### 2. 工具白名单按请求上下文动态生成

- `document_id`：只暴露指定文档检索工具；公共 Search/Extract 不出现在 Agent 工具列表中。
- 有登录用户但未指定文档：暴露个人知识库检索、Tavily Search、Tavily Extract 和基础模型能力。
- 游客：只暴露 Tavily Search、Tavily Extract 和基础模型能力，不暴露 Chroma 或任何用户数据工具。
- URL 输入：后端只允许 Extract，Agent 不得把 URL 改写成关键词搜索。
- 关键词输入：策略要求至少完成一次 Query Expansion；扩展查询最多 3 个，再允许 Agent 并行调用 Search。

工具执行器统一负责参数校验、单工具超时、最多一次重试、最大返回长度和不可信内容包装。网页内容永远作为数据，不作为系统指令。

### 3. Agent 使用有限状态机和结构化最终输出

Agent 状态包含 `route_intent`、`tool_calls`、`candidate_sources`、`query_plan` 和 `stop_reason`。允许的阶段为：`classify`、`expand_or_extract`、`retrieve`、`finalize`；最多 4 次工具调用或达到总研究超时即停止。

最终输出使用 Pydantic 结构化模型：路由、工具、候选数、保留数、来源、相关性评分、版本适配、冲突组和 fallback reason。非法输出、未知来源 ID、超过预算或缺少引用时由后端拒绝，不直接注入出题 Prompt。

### 4. Query Expansion 与证据过滤仍保留为强制质量闸门

Agent 对关键词输入先调用 Query Expansion 能力；如果该阶段失败，使用规范化原始主题作为唯一查询并记录降级。Search 结果或 Extract 页面块先做 URL/标题/正文去重，再由独立过滤器评分，默认阈值 `0.75`、最多保留 5 条。

过滤失败或全部低相关时不注入未过滤内容，直接使用基础模型。保留的证据携带来源 URL、标题、评分和检索时间，以便题目元数据追踪。

### 5. 游客采用匿名会话绑定和服务端用量控制

前端首次使用生成随机匿名会话标识，并通过请求头发送；后端只保存带服务端盐的哈希，不保存原始标识。生成任务、快照、进度和报告查询必须匹配该哈希，防止仅凭任务 ID 越权。

在 MySQL 中增加匿名用量计数或使用现有任务表按哈希统计，默认限制单会话并发任务数和每日任务数；限制值放入配置，超限返回明确的可重试错误。登录后不继承游客的个人数据，也不自动把匿名任务写入用户历史，除非已有明确的绑定流程。

### 6. 研究 Provider 注入生成服务，避免登录状态改变题目协议

增量生成服务继续只依赖统一的 `ResearchProvider` 接口。登录用户的 Provider 可使用 Chroma 和公共工具；游客 Provider 只使用公共工具。题目任务、轮询快照、逐题追加和答题进度接口保持现有路径和字段兼容，只扩展研究元数据和匿名会话校验字段。

### 7. 用功能开关和版本化缓存支持回滚

新增 `guest_generation_enabled` 和 `agentic_router_enabled` 开关。研究缓存键包含 Agent、Query Expansion 和过滤器版本；关闭 Agent 时回退到现有受控研究或基础模型，不删除任务和答题记录。数据库迁移只增加可空字段或新计数表，回滚时保留旧字段和旧任务数据。

## Risks / Trade-offs

- [Agent 调用增加延迟和 Token 成本] → 限制状态阶段、工具次数和总超时；缓存 Query Plan、搜索候选和过滤结果，并优先让首题使用已确认的最小证据集。
- [Agent 误选工具或越权访问文档] → 工具白名单由后端生成，Agent 输出不能扩大权限；所有工具调用在执行前再次校验。
- [相关性过滤误杀新概念] → 记录评分和理由，建立包含 Harness Engineering、RAG、React Hooks、URL 文档的评测集，定期校准阈值；无证据时仍可基础模型降级。
- [游客滥用公共搜索] → 匿名会话、IP 哈希、并发/每日额度和单任务预算组合限流；超限不影响已开始任务。
- [多进程部署下匿名额度不一致] → 用 MySQL 原子计数或后续引入共享限流存储，禁止只依赖进程内字典。
- [新增字段与旧任务不兼容] → 使用可空默认值、版本化快照解析和迁移前后双读；先灰度开启功能开关。

### 8. LangChain Agent API alignment

实现阶段使用 LangChain v1 的 `create_agent`，将后端动态生成的工具白名单作为 `tools` 传入，并通过 `ToolStrategy(PydanticModel)` 获取结构化最终输出；工具调用上限使用官方 `ToolCallLimitMiddleware` 配置全局和按工具预算。这样 Agent 仍然真正通过工具调用完成检索，但最终路由和证据包始终经过 Schema 校验。该选择基于 Context7 当前 LangChain OSS Python 文档，避免继续沿用旧版 AgentExecutor 接口。

## Migration Plan

1. 增加匿名会话校验字段、用量计数迁移和默认关闭的功能开关。
2. 实现游客任务创建、快照、进度和报告权限测试，确认登录用户行为不变。
3. 实现策略守门、有限 Agent、工具执行器和结构化证据过滤，先在登录用户灰度。
4. 将游客 Provider 接入增量任务，灰度开放低额度公共研究。
5. 运行后端 TDD、真实 DeepSeek/Tavily 冒烟、前端构建和微信开发者工具流程验证。
6. 出现成本、延迟或正确性问题时，关闭 Agent 或游客开关；保留任务数据并回退基础模型路径。
