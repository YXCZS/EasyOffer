## Context

现有 `Question` 在 DeepSeek 调用中一次返回题干、选项、答案和文字解析；增量模式逐题写入 generation task，前端通过轮询取得可答题的问题。微信小程序端不具备稳定的浏览器 DOM 环境，因此不在前端运行 Mermaid 或浏览器生图 SDK。项目已有 `uploads` 静态资源入口、MySQL 任务持久化和后台增量生成边界。本设计遵循 proposal 和 `quiz-explanation-visual-assets` 规格，并将图片作为题目解析的可选附加资源。

## Goals / Non-Goals

**Goals:**

- 让 DeepSeek 在生成文字解析时输出结构化、受约束的可视化意图和生图提示词。
- 使用阿里云百炼图片模型生成概念配图，并使用腾讯云 COS 保存稳定对象。
- 让文字题目先可用，图片任务异步执行，支持任务状态、有限重试、幂等和降级。
- 在 Taro 答题反馈区域展示 ready 图片、pending 状态和 failed 的纯文本回退。
- 兼容一次性和增量两种出题路径，以及没有可视化字段的历史题目。

**Non-Goals:**

- 不在小程序端运行 Mermaid.js、解析 Mermaid 或保存云存储密钥。
- 不改变 Agentic RAG、Tavily、Chroma、答题评分、报告生成和底部导航。
- 不实现用户手动编辑、重新绘图、图片分享、图片收藏或视频生成。
- 不保证图片为永久公开 URL；默认以 COS 对象 Key 为永久标识，按访问策略生成 URL。

## Decisions

### 1. 采用结构化可视化意图，而不是让图片模型直接读取整道题

`Question` 增加可选 `visualization` 对象，包含 `enabled`、`mode`、`type`、`image_prompt`、`alt_text`、`asset_id`、`image_url` 和 `status`。DeepSeek 只负责判断适配性和生成提示词，生图客户端只接受经过长度、字符和安全规则校验的提示词。这样能避免模型在图片任务中重新解释题意，也能对历史题目保持字段缺省兼容。

替代方案：直接把完整题解发送给生图模型。该方案提示词不可控，容易泄露个人知识库内容、生成题意外事实，也无法稳定关联图片和题目，因此不采用。

### 2. 文字生成和图片生成解耦

题目通过现有 DeepSeek 质量校验后立即追加到 generation task；图片任务在同一事务边界外异步执行。增量任务不等待图片，首题返回延迟保持由文字模型和证据检索决定。一次性流程也先返回可答题的 quiz，再由图片任务补齐资源状态。

图片状态通过 `pending -> generating -> uploading -> ready|failed` 表示。前端读取题目快照或刷新题目数据后即可看到最新状态；若当前接口暂时没有实时刷新图片，可在反馈展示时使用一次轻量刷新，不能阻塞下一题。

替代方案：在返回题目前串行等待生图和 COS。该方案会重新放大首题延迟并增加微信请求超时，不采用。

### 3. 使用百炼图片模型并保留模型配置

 后端通过 HTTP 客户端封装百炼图片 API，默认使用低成本的 `z-image-turbo`，不把模型名写死在业务逻辑中。该模型按单张图片请求调用（`n=1`），客户端兼容临时 URL 和 base64 响应，统一转换为受大小和 MIME 限制的字节流。生图请求必须设置超时、最大并发和每轮上限；同一题目的图片任务使用 prompt hash 幂等。

一次请求生成多图仅在百炼接口明确支持多个独立 Prompt 且返回结果可稳定对应时启用；否则按题目独立调用，避免将同一提示词的多张变体错误绑定到不同题目。

### 4. 使用腾讯云 COS 保存对象，默认私有访问

新增 COS 存储适配器，使用官方 `cos-python-sdk-v5` 的 `CosConfig`、`CosS3Client.put_object` 和对象 URL/签名 URL 能力。对象 Key 使用 `easyoffer/quiz-assets/{owner}/{quiz}/{question}/{prompt_hash}.webp`，数据库保存 `asset_id`、`cos_key`、MIME、尺寸和状态，不保存图片二进制。

本期按产品确认使用公开访问：COS 对象上传为公开可读，后端根据 `COS_PUBLIC_BASE_URL` 和对象 Key 生成稳定公开 URL，并将 URL 写入题目数据。COS SecretId、SecretKey、Bucket、Region 和公开域名只从环境变量读取，绝不进入题目 JSON、日志或前端包。若未来题目可能包含敏感知识库内容，应新增私有桶签名 URL 模式，而不是继续公开已有对象。

### 5. 新增图片资源表并与题目弱关联

增加 `quiz_visual_assets` 表，通过 `task_id/quiz_id/question_id` 关联题目，并以 `(task_id, question_id, prompt_hash)` 唯一键保证幂等。题目 JSON 中只保存可安全返回的状态和 asset_id/image_url 快照；对象路径和供应商错误信息以资源表为准。资源表迁移采用 `CREATE TABLE IF NOT EXISTS`，回滚时停止新任务并保留已有题目文字数据，删除表为可选的人工清理步骤。

### 6. 失败只影响图片，不影响题目

生图、下载、解码、校验、COS 上传或签名 URL 失败时记录结构化日志、递增有限重试次数并将状态设为 `failed`。生成服务返回的临时 URL 不会作为最终 URL 持久化。DeepSeek 题目、答题进度、评分和报告路径不依赖资源表，因此图片服务不可用时自动呈现纯文本解析。

### 7. 前端只渲染远程图片

Taro `Image` 使用 `aspectFit` 展示 COS 签名 URL，并处理 `pending`、`ready`、`failed` 和 `onError`。图片区域使用固定的最大高度和占位样式，不影响解析文本和底部操作按钮。图片加载失败时隐藏图片并保留 alt 文本或文字解析，不显示供应商错误详情。

## Risks / Trade-offs

- [百炼临时 URL 过期] -> 收到响应后立即下载，不把临时 URL 写入业务数据；下载失败按有限次数重试。
- [生图延迟增加后台负载] -> 使用队列/任务表、并发上限、每轮最多图片数和超时；不阻塞题目生成。
- [图片模型生成技术关系不准确] -> 由 DeepSeek 判断是否适合生图，提示词强调“教育示意图、不要虚构 API/参数”；流程和关系型内容优先使用未来可扩展的 Mermaid 分支，第一期默认只实现图片模式。
- [公开 URL 暴露题目相关图片] -> 当前产品已确认图片公开可访问；提示词过滤敏感凭据和原始文档全文，并保留未来切换私有签名 URL 的配置边界。
- [重复任务造成重复计费] -> prompt hash 唯一键、状态锁和任务重试上限，生成前先查询已有 pending/ready 资源。
- [个人知识库隐私泄露] -> 生图提示词只使用题目解析所需的最小摘要，过滤 URL、密钥、代码凭据和原始文档全文；日志不记录完整提示词。
- [旧题目缺少字段] -> Pydantic 默认可选值按 `disabled/none` 处理，前端采用字段存在性判断，不要求数据库回填。
- [COS 或百炼配置缺失] -> 应用启动不因图片配置失败而退出；图片功能标记 disabled，核心题目生成继续运行。

## Migration Plan

1. 增加可选配置和 `quiz_visual_assets` 表，执行启动迁移并验证已有题目可读。
2. 部署后端模型字段、生图客户端、COS 客户端和后台任务处理；默认图片功能关闭或限制在开发环境。
3. 配置百炼 API Key、图片模型、COS 私有桶、Region、Bucket 和签名 URL 参数后，小范围验证一轮题目。
4. 开启前端图片展示，观察生成成功率、延迟、COS 流量和失败降级日志。
5. 回滚时关闭图片功能开关即可；题目生成、答题和报告继续使用文字字段，资源表和已上传对象可保留待后续清理。
