## Context

当前知识库页面已经可以上传、处理、重试和删除用户文档，但题目生成入口只接受主题文本，无法把某一份文档作为唯一出题范围。现有普通题目生成流程会经过证据路由，可能使用用户知识库、Tavily 或基础知识，因此需要新增一个明确的“单文档专属模式”，同时保持未携带文档 ID 的请求完全兼容。

## Goals / Non-Goals

**Goals:**

- 在 `ready` 文档卡片中提供与原型一致的“开始闯关”入口，并将当前文档上下文带入现有生成中页面。
- 在后端建立可验证的单文档出题边界：文档必须属于当前登录用户且已处理完成。
- 让 Chroma 检索只返回指定 `document_id` 的分片；内容充足时严格基于文档出题，内容不足时使用不带外部检索内容的基础模型降级，不使用其他文档或联网内容凑题。
- 复用现有题目、答题、断点保存、报告和失败重试流程，不新增表、不改变普通主题请求协议的必填字段。
- 为专属请求记录可审计的证据元数据，便于排查是否误用了外部来源。

**Non-Goals:**

- 不在本变更中增加新的知识库文件类型、向量模型、数据库表或后台任务框架。
- 不改变普通主题的 Agentic RAG 路由策略，也不移除 Tavily Search/Extract。
- 不实现文档级权限共享、协作编辑、文档内容在线预览或题目数量自定义。

## Decisions

### 1. 用可选 `document_id` 表示专属模式

在 `QuizGenerateRequest` 和前端 `generateQuiz` 参数中增加可选 `document_id`。当该字段存在时，服务端将请求解释为当前单文档专属模式；未提供时沿用已有普通模式。客户端传入的文档名称只用于界面展示，服务端以数据库记录为准，避免伪造文档上下文。

相比新增独立 `/knowledge/{id}/quiz` 接口，这种方式可以复用生成中页面、错误处理、题目持久化和后续答题流程，且对已有调用保持向后兼容。

### 2. 在题目服务入口集中做归属与状态校验

`QuizService.generate`（或其路由前置服务）在执行证据检索前按当前用户 ID 查询文档：

- 找不到文档或文档不属于当前用户时返回统一的资源不存在/无权访问错误，不泄露文档信息；
- `processing`、`failed` 及其他非 `ready` 状态返回可识别的文档未就绪错误；
- 校验失败时不调用 Chroma、Tavily 或 DeepSeek，避免无效成本和越权侧信道。

选择服务层集中校验是为了覆盖未来的其他调用入口，而不是只依赖 HTTP 路由的单点保护。

### 3. 扩展知识库检索的元数据过滤

为现有知识库 `search` 增加可选 `document_id` 参数，并在 Chroma 查询时使用 `where={"document_id": <id>}`（若底层适配器不支持，则在统一适配层执行严格后过滤并再次验证结果）。证据构建函数接收该参数并只返回指定文档分片，同时检查所有结果的元数据 `document_id` 与请求值一致。

专属模式将证据路由固定为 `document_only`，跳过 Tavily Search/Extract 和用户其他文档。检索结果达到置信度阈值时，提示词只允许使用当前文档证据；结果为空或置信度不足时，清空证据上下文并调用基础模型生成，避免把低质量片段误当成文档事实。

### 4. 复用现有生成页面和会话模型

知识库卡片点击按钮后，将 `document_id` 和数据库返回的文件名写入生成页可读取的会话上下文，并以文件名作为显示主题；生成页仍展示现有生成动画、失败页和重试入口。请求成功后使用现有 `setQuiz` 创建答题会话。

为兼容断点续答，可在前端 `PracticeSession` 增加可选 `documentId`/`documentName` 字段；旧版本地会话反序列化时字段缺失按普通练习处理。后端已有题目记录的 `evidence_meta` 保存来源信息，不修改数据库表结构。

### 5. 证据审计元数据

专属模式生成结果的 `evidence_meta` 至少包含：`route="document_only"`、`document_id`、`used_personal_kb`、`used_web=false`、`used_base_model`、实际命中的分片数量；发生降级时追加 `fallback_reason="document_content_insufficient"`。普通模式继续写入现有元数据格式，避免报告和历史记录解析回归。

### 6. 错误与事务边界

文档校验或模型校验失败时，沿用现有可识别的 API 错误结构，让前端生成失败页显示具体原因并可重试。证据不足本身不属于失败；只有基础模型或最终 schema 校验失败时才不创建记录。只有题目完整通过现有 schema 校验后才创建 quiz/progress 记录。重试复用同一文档 ID，但重新读取最新的 `ready` 状态。

## Risks / Trade-offs

- [文档内容过短或与文件名主题不匹配] -> 清空不足的文档证据并使用基础模型生成，记录降级原因；不跨文档或联网补齐。
- [Chroma 版本或适配器不支持 `where` 过滤] -> 将过滤封装在知识库服务中，优先使用原生过滤，失败时执行结果级严格校验，并增加测试防止混入其他文档。
- [用户本地旧会话缺少新增字段] -> 新字段保持可选并在解析时提供默认值，现有普通练习照常恢复。
- [文档在生成期间被删除或状态变更] -> 服务层在每次生成请求重新校验，返回文档不可用错误，不创建新的 quiz 记录。
- [前端按钮布局在小屏设备上拥挤或颜色与现有界面不协调] -> 复用现有卡片操作区的 flex 布局和主题色/状态色 token，按钮固定最小触控尺寸，仅在 `ready` 状态渲染并执行真机/开发者工具检查。

## Migration Plan

1. 先发布后端可选字段、文档校验、Chroma 过滤和证据元数据逻辑；不需要数据库迁移。
2. 添加后端单元测试和接口兼容测试，确认未携带 `document_id` 的请求结果与旧流程一致。
3. 发布前端卡片入口、生成页上下文传递和会话可选字段；旧客户端仍可调用普通模式。
4. 逐步验证 ready 文档专属出题、非 ready 拒绝、跨用户拒绝、内容不足时基础模型降级和普通主题回归。
5. 回滚时先回退前端入口，再回退后端专属分支；保留可选请求字段不会影响已有数据和旧会话。
