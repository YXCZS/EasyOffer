## Purpose

让 EasyOffer 能够基于最新、可核验的公开资料生成程序员技术面试题，降低大模型训练数据滞后、概念误判和无依据题解对用户学习结果的影响。

## ADDED Requirements

### Requirement: 检索并建立可核验的主题证据

系统 MUST 在生成题组前，根据用户输入、岗位方向和难度检索公开资料，并为本轮请求建立可追溯的证据集合。每个进入证据集合的来源 MUST 至少包含标题、URL、站点、抓取时间和可支持结论的内容摘要；版本敏感主题 MUST 尽量包含官方文档、标准规范或维护者资料。

#### Scenario: 新技术概念能够通过最新资料进入生成流程

- **WHEN** 用户输入 `Harness Engineering`，并选择任意程序员岗位方向
- **THEN** 系统 MUST 先检索与软件工程、开发流程或相关技术语境匹配的公开资料，再决定是否生成题组，不得仅依据固定技术名词表或模型旧知识直接判定

#### Scenario: 来源满足最低可信条件

- **WHEN** 检索得到多个与主题匹配且可访问的来源
- **THEN** 系统 MUST 至少保留两个相互独立的来源；对于版本敏感主题，证据集合 MUST 优先包含至少一个权威或官方来源

#### Scenario: 没有足够证据时拒绝伪造题目

- **WHEN** 搜索结果为空、来源不可访问、来源与主题不匹配，或无法形成满足最低条件的证据集合
- **THEN** 系统 MUST 返回“来源不足，暂时无法可靠生成”的可识别失败结果，且 MUST NOT 使用模型常识补齐后返回看似正常的题组

### Requirement: 识别主题范围和歧义

系统 MUST 结合用户输入、岗位方向和检索证据判断主题是否属于程序员技术面试范围。系统 MUST 支持尚未进入固定词表的新技术、英文术语、缩写和公司内部技术名词；对于无法确定语境的多义输入，系统 MUST 返回待澄清状态，而不是猜测一个领域直接出题。

#### Scenario: 明确属于程序员面试内容

- **WHEN** 用户输入与软件开发、计算机基础、编程语言、框架、数据库、网络、系统设计、AI 工程或其他已支持岗位方向相关
- **THEN** 系统 MUST 进入证据校验和题组生成流程

#### Scenario: 输入不属于支持范围

- **WHEN** 用户输入明确属于旅游、烹饪、健身、文学或其他非程序员技术面试领域
- **THEN** 系统 MUST 返回现有领域不支持错误，并给出程序员技术面试主题示例；系统 MUST NOT 调用题目生成链返回题组

#### Scenario: 输入存在多种技术解释

- **WHEN** 用户输入是一个在不同技术领域含义不同的缩写或术语，且当前岗位和来源不足以确定唯一语境
- **THEN** 系统 MUST 返回主题待澄清结果，并提供不超过三个候选解释或补充信息提示；用户补充后才允许重新生成

### Requirement: 题目和解释必须受证据约束

系统 MUST 基于本轮证据集合生成结构化题组，题目数量、题型和现有字段规则 MUST 保持兼容。每道题的核心答案、解释和版本前提 MUST 能映射到一个或多个来源片段；系统 MUST 进行独立质量检查，确认答案存在于选项、单选或判断题答案唯一、题目无明显重复且不存在证据之外的关键断言。

#### Scenario: 证据充分时生成可作答题组

- **WHEN** 主题判断通过且证据集合满足最低可信条件
- **THEN** 系统 MUST 返回现有可渲染的六道结构化题目，并为每道题返回知识点、常见误区、适用版本或前提和来源引用标识

#### Scenario: 质量检查发现题目与证据不一致

- **WHEN** 独立检查发现题目答案无法由来源支持、题干有歧义、答案不唯一、题目重复或模型添加了来源中没有的关键事实
- **THEN** 系统 MUST 先尝试有限次数的重新生成或修正；仍不通过时 MUST 返回生成失败，并且 MUST NOT 把未通过检查的题组交给用户

#### Scenario: 来源之间存在版本或结论冲突

- **WHEN** 两个或多个可靠来源对同一结论给出不同版本、条件或实现行为
- **THEN** 系统 MUST 在题目或解释中标明适用版本/条件，或返回需要澄清的冲突结果；系统 MUST NOT 隐藏冲突并声称存在无条件唯一答案

### Requirement: 向用户提供来源和时效信息

系统 MUST 在题组响应中提供本轮检索时间、内容时效状态、AI 生成标识和来源清单；来源清单 MUST 展示站点、标题、版本或发布时间（如可获得）以及可打开的 URL。题目引用的来源 MUST 能与来源清单关联，且前端展示不得泄露正确答案到用户提交答案之前。

#### Scenario: 用户查看生成题组的来源

- **WHEN** 题组生成成功且用户打开来源区域
- **THEN** 用户 MUST 能看到来源标题、站点、检索/发布时间信息和原文入口，并能知道题目内容由 AI 生成且经过自动校验

#### Scenario: 来源链接失效

- **WHEN** 来源在生成后不可访问或返回失效状态
- **THEN** 系统 MUST 保留本轮证据快照用于解释和审计，并在前端标记来源暂不可访问，不得把失效链接伪装成正常可用来源

### Requirement: 外部服务失败时保持可恢复且不降级为无依据出题

系统 MUST 对 Firecrawl 搜索/抓取和 DeepSeek 生成分别设置超时、有限重试和可识别错误；相同或高度相似主题在允许的新鲜度窗口内可以复用已通过质量检查的证据或题组。任何外部服务失败 MUST 通过现有生成中/失败页面给出明确提示和重试入口。

#### Scenario: Firecrawl 暂时不可用

- **WHEN** Firecrawl 超时、限流、鉴权失败或返回不可解析结果
- **THEN** 系统 MUST 返回可识别的检索服务失败状态和重试提示，且 MUST NOT 静默使用没有本轮证据的模型知识生成题组

#### Scenario: 允许复用新鲜缓存

- **WHEN** 相同主题、岗位和版本条件命中仍在新鲜度窗口内且已经通过质量检查的缓存证据或题组
- **THEN** 系统 MAY 复用缓存并在响应中标明缓存生成时间和来源时间，不得隐瞒缓存不是本次实时检索

#### Scenario: 用户重试生成

- **WHEN** 用户在生成失败页面点击重试
- **THEN** 系统 MUST 使用新的请求尝试重新检索或生成，并保持现有输入、岗位和难度设置，不得重复提交已完成的答题记录
