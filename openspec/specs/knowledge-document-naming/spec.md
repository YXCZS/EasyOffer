# knowledge-document-naming Specification

## Purpose
让用户能够用易识别的自定义名称管理个人知识库，并在文档列表和开始答题入口中看到一致、清晰的名称，同时保持文档身份和向量内容稳定。

## Requirements

### Requirement: 文档所有者可以修改知识库名称

系统 MUST 允许已登录且拥有该文档的用户修改文档名称。名称 MUST 去除首尾空白、不能为空，并遵守现有文档名称长度限制；修改成功后 MUST 立即返回最新名称。

#### Scenario: 成功修改文档名称

- **WHEN** 文档所有者输入合法的新名称并确认保存
- **THEN** 系统更新该文档的展示名称，知识库列表刷新为新名称，文档 ID、状态、分片数量和向量内容保持不变

#### Scenario: 名称为空或超出限制

- **WHEN** 用户提交空名称或超过长度限制的名称
- **THEN** 系统返回可读的参数错误，不更新原名称，也不触发重新解析和重新向量化

#### Scenario: 修改其他用户的文档名称

- **WHEN** 用户 A 使用用户 B 的 `document_id` 请求修改名称
- **THEN** 系统拒绝请求或返回不存在结果，且不泄露用户 B 的文档名称和内容

### Requirement: 自定义名称必须用于文档管理入口

系统 MUST 在知识库列表、文档编辑交互和该文档后续开始答题入口中展示最新自定义名称；文档的内部 ID 和单文档检索范围 MUST 不因改名改变。

#### Scenario: 使用新名称开始答题

- **WHEN** 用户修改 ready 文档名称后点击该文档的“开始答题”
- **THEN** 系统以原 `document_id` 进入现有题目生成流程，并将新名称作为练习展示名称，不跳转到其他页面或其他文档

#### Scenario: 旧名称兼容

- **WHEN** 用户打开已有的未完成练习或历史记录
- **THEN** 系统仍能通过保存的练习和文档 ID 恢复答题；名称变化不得导致题目、进度或报告丢失

### Requirement: ready 文档入口文案必须统一为“开始答题”

知识库中状态为 `ready` 的文档 MUST 显示“开始答题”操作；状态为 `processing` 或 `failed` 的文档不得显示可执行的开始答题操作，失败文档继续显示重试入口。

#### Scenario: ready 文档显示开始答题

- **WHEN** 用户打开知识库列表且文档状态为 `ready`
- **THEN** 文档卡片显示“开始答题”，点击后进入现有生成中页面并携带该文档 ID

#### Scenario: 不可用文档隐藏开始答题

- **WHEN** 文档状态为 `processing` 或 `failed`
- **THEN** 文档卡片不显示可执行的“开始答题”，并显示处理状态或重试操作
