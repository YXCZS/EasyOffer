# first-question-latency Specification

## Purpose
让逐题生成真正改善用户等待体验：第一道题在有限时间内可用并进入答题页，后续题目在用户作答期间继续生成，同时避免联网、图片或单题失败导致页面长时间空白。

## Requirements

### Requirement: 生成任务必须支持首题就绪

系统 MUST 在生成任务创建后异步执行出题，并在第一道题持久化成功后立即将其作为可答题结果暴露给前端，不得等待其余题目或图片全部完成。

#### Scenario: 第一题生成成功
- **WHEN** 后台完成并保存第一道题
- **THEN** 任务快照包含至少一道题，前端进入答题页，后续题目继续后台生成

#### Scenario: 后续题目仍在生成
- **WHEN** 用户已经进入答题页但下一道题尚未生成
- **THEN** 页面显示继续生成状态，并允许刷新或等待，不得把任务误报为整轮失败

### Requirement: 首题证据准备必须有界等待

系统 MUST 为普通登录用户的联网证据准备设置独立的首题截止时间；达到截止时间时，系统 MUST 使用已经获得的高相关证据或基础模型兜底生成第一题，不得无限等待完整搜索、过滤或后续题目规划。

#### Scenario: 联网证据在截止时间内完成
- **WHEN** Tavily 搜索和证据过滤在首题预算内返回有效结果
- **THEN** 第一题使用有效证据生成，并记录联网来源

#### Scenario: 联网证据超过截止时间
- **WHEN** 搜索、过滤或路由超过首题预算
- **THEN** 取消或放弃阻塞首题的等待，使用已有证据或基础模型生成第一题，并记录降级原因

### Requirement: 生成状态和轮询频率必须反映阶段

系统 MUST 为前端提供至少可区分 queued、generating、首题可用、completed、failed/expired 的任务状态或等价字段。前端 MUST 在首题未就绪时使用较短轮询，在首题就绪后使用较长轮询，并在连续请求失败时退避。

#### Scenario: 首题尚未生成
- **WHEN** 生成页收到 running 任务且题目数量为零
- **THEN** 前端按短间隔轮询，继续展示生成中状态

#### Scenario: 首题已经生成
- **WHEN** 任务快照包含第一道题但状态仍为 generating
- **THEN** 前端停止生成页轮询并进入答题页，答题页按较长间隔拉取后续题目

### Requirement: 图片生成不得阻塞题目

系统 MUST 将题目配图生成、下载和 COS 持久化作为独立异步工作。图片失败、超时或配置缺失时，题目、解析和答题流程 MUST 继续可用。

#### Scenario: 开启图片且图片仍在生成
- **WHEN** 题目已经生成但图片状态为 pending
- **THEN** 前端显示文字题目和解析，并提示配图生成中

#### Scenario: 图片生成失败
- **WHEN** 百炼或 COS 操作最终失败
- **THEN** 图片标记为 failed，题目仍可正常作答和生成报告
