# agentic-evidence-routing Specification

## Purpose
为技术面试题目生成提供可解释、可控且失败可降级的证据路由，使个人知识库和联网资料能够按问题意图、时效性与证据质量组合使用，而不是依赖固定技术词表或“新概念必然联网”的单一规则。

## Requirements

### Requirement: 系统必须为每次题目生成建立受控的证据路由计划

系统 MUST 在题目生成前根据用户主题、岗位方向、难度、输入类型、个人知识库可用性和时效性要求，生成一个结构化路由计划。计划 MUST 指明是否调用个人知识库、Tavily Search、Tavily Extract 或基础模型降级，并包含路由原因和调用预算。

#### Scenario: 普通技术主题由路由器选择本地优先策略
- **WHEN** 用户输入普通技术主题且当前用户存在可用个人知识库
- **THEN** 系统 MUST 允许路由器优先计划个人知识库检索，并为后续证据不足时的联网补充保留预算

#### Scenario: URL 输入强制使用页面提取
- **WHEN** 用户输入可识别的 HTTP 或 HTTPS URL
- **THEN** 系统 MUST 将 Tavily Extract 作为首选工具，不得仅依赖关键词搜索摘要

#### Scenario: 明确的最新内容要求触发联网
- **WHEN** 用户明确要求最新、当前版本或指定时间范围的信息
- **THEN** 系统 MUST 计划调用 Tavily Search，即使个人知识库存在相关内容

### Requirement: 系统必须评估个人知识库证据后再决定是否联网

系统 MUST 对个人知识库召回结果评估语义相关性、主题覆盖度、可回答性和冲突情况，并将结果归类为高置信度、中置信度或低置信度。系统 MUST NOT 仅因召回结果数量大于零就判定检索成功。

#### Scenario: 高置信度本地证据直接用于出题
- **WHEN** 个人知识库证据与主题高度相关、覆盖足够且不存在明显冲突
- **THEN** 系统 MUST 可以只使用个人知识库生成题目，并避免不必要的 Tavily 调用

#### Scenario: 中置信度证据触发混合检索
- **WHEN** 个人知识库证据部分相关但存在未覆盖的关键知识点
- **THEN** 系统 MUST 保留本地证据并调用 Tavily Search 补充缺失内容

#### Scenario: 低置信度证据触发联网替代
- **WHEN** 个人知识库没有命中、结果低相关或无法支撑题目
- **THEN** 系统 MUST 优先使用 Tavily Search 重新获取外部证据，并不得把低相关片段作为主要事实依据

### Requirement: 系统必须以来源可追溯的方式融合检索证据

系统 MUST 对个人资料、搜索结果和页面提取结果保留来源类型、来源标识、URL（如有）和抓取时间，并在传给题目生成模型时明确区分来源。系统 MUST 去重相似片段并限制最终证据上下文长度。

#### Scenario: 混合证据生成题目
- **WHEN** 路由器同时获得个人资料和网络资料
- **THEN** 系统 MUST 将两类证据分别标记后再提供给生成模型，并保留网络来源 URL

#### Scenario: 网络资料相互冲突
- **WHEN** 不同来源对版本或概念定义存在冲突
- **THEN** 系统 MUST 标记冲突并优先保留可识别的官方或一手来源，不能静默拼接为单一事实

### Requirement: 系统必须控制单次请求的成本、延迟和工具调用范围

系统 MUST 对 Router Agent、Chroma、Tavily Search 和 Tavily Extract 设置单次请求调用预算、超时和上下文长度限制。系统 MUST 根据主题复杂度和时效性动态选择搜索深度、结果数量和页面提取深度，并禁止无上限的 Agent 工具循环。

#### Scenario: 简单主题使用低成本搜索配置
- **WHEN** 主题简单且仅需要少量外部摘要
- **THEN** 系统 MUST 使用低搜索深度和较少结果数量，并在摘要足够时不调用页面提取

#### Scenario: 复杂主题使用增强检索配置
- **WHEN** 主题复杂、版本敏感或初次结果不足以支撑出题
- **THEN** 系统 MUST 在调用预算内提高搜索深度或追加有限的页面提取

### Requirement: 外部检索失败不得阻断原有题目生成流程

系统 MUST 捕获 Tavily 超时、鉴权、配额和解析错误，记录结构化失败原因，并按“可用个人证据、压缩后的已有证据、原有基础模型”顺序降级。系统 MUST 避免同一请求因重复研究调用而无故增加延迟或成本。

#### Scenario: Tavily 失败但本地证据可用
- **WHEN** Tavily 调用失败且个人知识库存在高置信度证据
- **THEN** 系统 MUST 使用个人证据继续生成题目，并在证据元数据中记录联网降级原因

#### Scenario: 所有证据源不可用
- **WHEN** Chroma 和 Tavily 均不可用或超时
- **THEN** 系统 MUST 按现有基础模型流程尝试生成题目，不得让检索异常破坏答题、报告和断点续答功能

### Requirement: 题目生成结果必须经过证据约束和兼容性校验

系统 MUST 校验生成结果的 JSON 结构、题目数量、主题相关性和证据使用约束。新增路由元数据 MUST 向后兼容现有题目生成接口，现有前端不得因缺少新增元数据而失败。

#### Scenario: 证据充分时生成标准题目
- **WHEN** 证据上下文通过评估且 DeepSeek 返回合法结构
- **THEN** 系统 MUST 返回现有格式的题目，并附带可选的来源类型、工具和降级元数据

#### Scenario: 生成结果结构非法
- **WHEN** DeepSeek 返回缺少必填字段或不符合题目数量要求的结果
- **THEN** 系统 MUST 执行一次受控重试或返回现有格式的生成失败信息，不得返回不可解析数据
